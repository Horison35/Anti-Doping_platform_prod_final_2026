# ЛОГИКА ПРОЕКТА · Антидопинговая платформа поддержки принятия решений

> Обязательное чтение для агента-кодера и разработчиков. Формулировки §3 — утверждённые,
> менять только по решению владельца проекта. Структура репозитория — в STRUCTURE.md.

## 1. Назначение и принципы

Платформа приоритизирует антидопинговую работу: показывает, в каких видах спорта и
субъектах РФ риск нарушений антидопинговых правил выше и что конкретно делать.
Целевая аудитория — работники антидопинговой сферы (не спортсмены, не тренеры).

Несущие принципы:
- **Модель ранжирует, код решает и формулирует, LLM собирает и резюмирует.**
  Proba и зоны риска — из ML-модели (причина зоны выводится из её сработавших
  правил lag/rolling). Приоритеты, квадранты и все обоснования на дашбордах —
  детерминированный код: подстановка причины модели и критериев рейтинга в
  утверждённые шаблоны siar/rules.py; одинаковые входы дают одинаковую фразу.
  LLM (Claude API) — только сбор новостей в АД-Мониторе и текстовые резюме
  дайджестов по готовым числам. Ни одно число и ни одно обоснование зон и
  приоритетов LLM не порождает.
- **База дисквалификаций — истина.** Новости — ранний сигнал до подтверждения базой.
- **Зону риска задаёт только модель.** Рейтинги РУСАДА зону не меняют — они добавляют
  вторую ось (качество антидопинговой работы) и определяют приоритет и рекомендацию.
- **Воспроизводимость.** Каждый прогон — снапшот (входные файлы + версия модели);
  любой вывод проверяем по исходным данным; потери строк только явные, через аудит.
- **Внешних агентов в контуре нет.** Всё критическое — код + Claude API.

## 2. Данные и потоки

### Источники
1. **База дисквалификаций российских спортсменов** (xlsx, ~2,3 тыс. записей с 2004 г.).
   Очистка и агрегация до сетки: вид спорта × субъект РФ × квартал. ФИО из контура
   вычищаются на входе — модель, БД и витрины работают только на агрегатах.
2. **Рейтинг ОСФ РУСАДА** (PDF, 142 федерации, 9 критериев: Стратегия, План-график,
   Регионы, Сайт, Семинар, Соглашение, Допуск, Мониторинг, Инфо; критерий выполнен
   при значении ≥ 1; сумма до 100, порог высокого рейтинга — 80).
3. **Рейтинг регионов РУСАДА** (xlsx, 89 субъектов, 3 блока критериев, максимум 190;
   порог высокого рейтинга — 130).
4. **АД-Монитор** — ежедневный новостной мониторинг (Claude API по скиллу).
   Охват — все спортивные источники, международные и российские: антидопинговые
   органы (РУСАДА, WADA, AIU, ITIA, USADA, CAS и др.) плюс общеспортивные СМИ.
   Назначение двойное: (1) понятная всем лента/дайджест на платформе;
   (2) доп-критерии риска по российским видам спорта (см. §3). Выход строго
   по JSON-контракту v15; записи без первичного источника не публикуются.

### Поток
watcher/загрузчики → верификация кодом (схемы, дедуп, матчинг, инварианты) →
PostgreSQL (снапшоты) → ML-прогон (CatBoost) → SIAR v2 → FastAPI → платформа/отчёты.

### Модель
Обученный ансамбль CatBoost (5 сидов), задача — ранжирование связок вид × регион
по вероятности нарушения в следующем квартале. Признаки — lag/rolling по истории
базы. Правила зон (порядок проверки RED → ORANGE → GREEN, ровно одна зона):
- **RED** — lag_1q + lag_2q > 0 (всплеск последних двух кварталов);
- **ORANGE** — rolling_mean_8q ≥ 0.25 или rolling_sum_4q ≥ 2 (историческая повторяемость);
- **GREEN** — всё остальное.
proba не калибрована: в интерфейсах показывать ранги/перцентили и зоны, сырую proba —
только аналитику по клику. Метрика качества — Lift@K, не precision.
Прогноз обновляется квартальным тактом; внутриквартальные новости идут флагами,
в признаки не попадают (защита от расхождения train/serve).

### Двухосевая логика (уточнение области действия)
Для ОСФ двухосевая логика исходная и не требует изменений: ось 1 — зона модели по
виду спорта (агрегат model_risks.csv), ось 2 — балл рейтинга федерации.
Для регионов (утверждено) прежняя одноосевая логика v4 (зона напрямую по баллам)
упразднена и заменена той же двухосевой: зона модели региона = наихудший сигнал
агрегации по региону (sort RED→ORANGE→GREEN, внутри по proba убыв.,
groupby(Регион).first() — файл region_risks.csv), вторая ось — балл рейтинга регионов.

## 3. SIAR v2 — приоритеты и утверждённые формулировки

Входы: зона модели (RED/ORANGE = «систематичность», GREEN = «нет систематичности»,
NO_DATA = «нет данных модели») и балл рейтинга (порог: ОСФ 80, регионы 130).
Подстановки: {причина} — из модели; {критерии} — перечень невыполненных; {баллы} — балл.

**A. Систематичность + рейтинг ниже порога → Приоритет 1**
Обоснование: «Рисковый по модели: {причина}. Усугубляется невыполнением критериев
рейтинга РУСАДА: {критерии}».
Рекомендация: «Приоритизировать работу по невыполненным критериям рейтинга;
выстроить системную антидопинговую работу совместно с федерацией/регионом».

**B. Систематичность + рейтинг высокий → Приоритет 2**
Обоснование: «Рисковый по модели: {причина}; при этом антидопинговая работа по
рейтингу РУСАДА на высоком уровне ({баллы})».
Рекомендация: «Усилить антидопинговое образование: семинары и вебинары для
спортсменов и персонала; адресные информационные кампании в виде спорта / регионе;
беседы с заинтересованными сторонами; совместный план профилактики с федерацией;
усиленный мониторинг ситуации».

**C. Нет систематичности + рейтинг ниже порога → Приоритет 3 · статус «потенциальный риск»**
Обоснование: «По истории нарушений {вид спорта/регион} рисковым не является, однако
из-за невыполнения критериев рейтинга РУСАДА ({критерии}) может стать рисковым —
антидопинговая работа не проводится или проводится недостаточно».
Рекомендация: «Приоритизировать работу по невыполненным критериям рейтинга;
превентивная работа с федерацией и регионом».
Для NO_DATA начало обоснования заменяется на: «Данных модели нет, однако…» (далее так же).

**D. Нет систематичности + рейтинг высокий → Приоритет 4**
Обоснование: «По истории нарушений рисковым не является; антидопинговая работа по
рейтингу РУСАДА на высоком уровне ({баллы})».
Рекомендация: «Поддерживать текущий уровень; плановый мониторинг ситуации».
Для NO_DATA добавляется оговорка «данных модели нет».

**Зона внимания (не меняет приоритет).** Рейтинг высокий, но есть невыполненные
критерии → к обоснованию B/D добавляется: «Зона внимания: {критерии}».

**Доп-критерий из мониторинга (не меняет зону и приоритет).** По каждому российскому
виду спорта код считает число подтверждённых допинг-событий из АД-Монитора за
скользящие 30 и 90 дней (санкции, отстранения, расследования). Отображается в
карточках и ховерах: «Сигналы мониторинга: N за 30 дней». В признаки модели не
входит до валидации backtest'ом; считает код, не LLM.

Запреты формулировок: не упоминать тестирование в рекомендациях; не использовать
служебный жаргон (ml_feed, SIAR, пайплайн, proba без пояснения) в текстах для людей.

## 4. Представление (гармония интерфейсов)

Единый визуальный язык от Excel до веб-платформы:
- зона модели = цвет: RED #DC2626 · ORANGE #F59E0B · GREEN #10B981 · NO_DATA #94A3B8;
- приоритеты (квадранты, scatter) = QUADRANT_COLORS: П1 #DC2626, П2 #F59E0B,
  П3 #3B82F6, П4 #10B981; scatter красится по приоритетам, бары и Excel — по зонам,
  не смешивать;
- статус «потенциальный риск» — единый маркер на всех экранах;
- у каждой точки/строки в ховере — обоснование SIAR v2 целиком (человеческий текст);
- палитра и шрифты: INK #0F2D52, SUB #7C8DA6, GRID #EEF2F7, Inter;
- индекс риска в интерфейсах = перцентиль proba в текущем прогнозе (0–100), не proba×100;
- на каждом дашборде и в каждой таблице — селектор объёма выборки: Топ-10 / Топ-20 /
  Топ-50 / все записи (как на эталонном макете AD-Monitor); данные от пользователя
  не скрываются — доступен любой срез и любая запись;
- все дашборды — интерактивный Plotly (ховеры, фильтры ФО/зона/приоритет,
  переключатель снапшотов), plotly подключается с CDN.

## 5. Инварианты (существуют как тесты; нарушение = прогон не выдаётся)

1. Строки итоговой таблицы + «Не сопоставлено» = N источника (полнота, ничего не
   теряется молча).
2. Сумма строк по приоритетам 1–4 = числу строк итога.
3. Каждая строка: ровно одна зона и ровно один приоритет.
4. Нет RED/ORANGE в приоритетах 3–4; нет GREEN в приоритетах 1–2.
5. Нет рейтинга ≥ порога в приоритетах 1/3; нет рейтинга < порога в приоритетах 2/4.
6. Матчинг: запрещено вхождение подстроки («бокс» ≠ «кикбоксинг»); морфологическая
   устойчивость обязательна («плавание» ≈ «плавания»); каждый матч — в аудит
   с типом и уверенностью.
7. Записи мониторинга: только с первичным source_url, проверенным кодом; дата в окне;
   сторонние агентские данные без первичного подтверждения не публикуются вовсе.
8. Каждый прогон привязан к снапшоту входных файлов (sha256) и версии модели.

## 6. Мониторинг (АД-Монитор) — краткий свод правил

Полнота по чек-листу: 16 обязательных строк матрицы источников (РУСАДА ×3, Минспорт,
Кремль, федерации, СМИ РФ; WADA ×2, AIU ×2, ITIA, USADA, UKAD, CAS, ITA, FISU,
EN-агрегаторы) + календарные триггеры (турниры, месячная статистика РУСАДА,
список AIU 1-го числа, анонсы прошлых выпусков). Каждая строка получает статус
«найдено/пусто/недоступен». Неподтверждённое — флагом мимо модели, снимается за два
выпуска. В дайджесте нет служебного жаргона, санкции пофамильно (публичные решения),
одна санкция = одна строка, пропуски = «н/д». Дайджест — по шаблону
monitor/digest_template.html; язык — понятный неспециалисту: лента и дашборд
мониторинга читаются любым пользователем платформы. Общеспортивные СМИ, российские
и международные, — обязательные строки матрицы наравне с антидопинговыми органами.

## 7. Эксплуатация

Cron: watcher рейтингов — еженедельно; АД-Монитор — раз в 4 дня (промышленный контур,
2026-07: по антидопинговой теме публикации выходят нечасто — ежедневный прогон давал
много пустых итераций и лишний расход токенов; window_days синхронизирован с
частотой прогона — см. monitor/run_daily.sh); ML-прогон — при обновлении базы
дисквалификаций (автоматически, по факту нового файла) и по закрытию квартала;
backtest — ежеквартально и при каждом автопереобучении (сравнение прогноз/факт,
контроль дрейфа модели, Lift@K кандидата против действующей версии). ALERT'ы
парсеров — в журнал и в отчёт. Доступ к платформе — по паролю (роли по пользователям
— явно отложенная задача, см. README/DEPLOY). Бэкапы PostgreSQL — ежедневно.

Инструкция пользователя: docs/USER_GUIDE.md — что означают зоны, приоритеты и статус
«потенциальный риск», как читать матрицу квадрантов и heatmap, как пользоваться
селектором Топ-N/все записи и фильтрами; обновляется с каждым релизом. На платформе —
экран «Справка» с тем же содержанием (пункт уже заложен в эталонном макете AD-Monitor).
