# Антидопинговая платформа поддержки принятия решений

Система приоритизации антидопинговой работы: показывает, в каких видах спорта и субъектах РФ
риск нарушений антидопинговых правил выше и что конкретно с этим делать. Совмещает прогнозную
модель (CatBoost, история дисквалификаций), официальные рейтинги РУСАДА (ОСФ и регионов) и
новостной мониторинг (АД-Монитор) — в единую приоритизацию SIAR v2.

Целевая аудитория — сотрудники антидопинговой сферы (не спортсмены, не тренеры).

## Как открыть дашборд

Платформа развёрнута здесь: **https://antidoping-platform.duckdns.org**

1. Откройте ссылку в браузере (компьютер или телефон).
2. Введите пароль доступа. Если пароля нет — напишите на **kirillvolobuev2022@gmail.com**.
3. Прочитайте вступительный экран и нажмите «Продолжить».
4. Готово — на главном экране сразу видно текущее состояние по приоритетам.

Разделы платформы: **Обзор** (для руководителя — 30 секунд на всё), **Приоритеты**
(полный анализ, фильтры, карточка «почему именно так» по клику), **История** (динамика по
кварталам), **АД-Монитор** (новостной дайджест), **Выгрузка** (Excel/CSV без интерактива),
**О данных** (для внешней проверки — источники, даты, воспроизводимость), **Справка**
(как читать зоны/приоритеты).

## Несущие принципы

- **Модель ранжирует, код решает и формулирует, ИИ собирает и резюмирует новости.** Ни одно
  число и ни одно обоснование зоны/приоритета ИИ не порождает — это детерминированный код по
  утверждённым правилам (`siar/rules.py`). Этот принцип не имеет исключений ни в одном модуле.
- **База дисквалификаций — истина**, новости — ранний сигнал до подтверждения базой.
- **Воспроизводимость.** Каждый прогон — снапшот входных файлов (sha256) + версия модели;
  повторный расчёт на тех же данных даёт тот же результат (проверяется тестами).
- **ФИО не попадают в БД и в интерфейсы модели/рейтингов** — только агрегаты вид спорта × регион.
  Исключение — лента АД-Монитора: она «переопубликовывает» уже официально опубликованные
  санкции (WADA/ITA/РУСАДА). Это отдельный, осознанный кейс, не отход от правила выше. В
  запросах к внешним ИИ-моделям (письменная аналитика дайджеста) ФИО не участвуют вовсе —
  туда уходят только обезличенные агрегаты (категория/вид спорта/дата).
- **Доступ — по паролю, без логинов.** Ролевой доступ по пользователям — явно отложенная
  задача (см. «Что не сделано» ниже).

Подробности — в [LOGIC.md](LOGIC.md) (логика и инварианты) и [STRUCTURE.md](STRUCTURE.md)
(структура репозитория, статус модулей, порядок сборки).

### Прогон модели/SIAR вручную (без Docker)

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt

python ml/predict.py --model ml/artifacts/ВАШ.pkl --meta ml/artifacts/ВАШ.json \
    --data "база_дисквалификаций.xlsx" --out predictions/
python siar/osf_report.py --pdf "Рейтинг-ОСФ.pdf" \
    --risks-csv predictions/model_risks.csv --out reports/
python siar/region_report.py --xlsx "Рейтинг-регионов.xlsx" \
    --risks-csv predictions/region_risks.csv --out reports/
python db/loaders/load_ml_run.py --data "база_дисквалификаций.xlsx" \
    --grid predictions/full_grid.csv --registry predictions/registry_agg.csv \
    --meta ml/artifacts/ВАШ.json --period "2026 Q3"
python db/loaders/load_siar_run.py --kind osf --source "Рейтинг-ОСФ.pdf" \
    --report reports/osf_risk_final.xlsx --meta ml/artifacts/ВАШ.json
```

Примеры готовых выходов без запуска модели — в `predictions_examples/` и `reports/examples/`.

## Что нужно докинуть руками (в репозитории нет намеренно)

- `ml/artifacts/*.pkl` — обученный ансамбль (модель не переобучается агентом-кодером, только
  переносится; см. STRUCTURE.md). На сервере уже развёрнут и зарегистрирован как активная версия.
- Реестр дисквалификаций (xlsx) — содержит ФИО, не публикуется в git.
- `ml/antidoping_model_production.ipynb` — методика обучения. Без него автопереобучение
  (`ml/retrain.py`) работает только в режиме «обновить прогноз действующей моделью на новых
  данных»; само обучение кандидата пропускается с понятной причиной в логах — см. DEPLOY.md.
- `.env` с реальными секретами — заполняется из `.env.example`.

## Что не сделано (открыто, не скрыто)

- Ролевой доступ по пользователям (сейчас — один общий пароль на всю платформу).
- Обучение новой версии модели (нужен ноутбук `antidoping_model_production.ipynb` — см. выше).
- АД-Монитор на сервере требует один ручной шаг — вход в Claude Code (`claude login`) под
  вашей подпиской; после этого включить таймер (`systemctl enable --now antidoping-monitor.timer`).
